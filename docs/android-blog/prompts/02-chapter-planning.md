# 提示词 ②　章节规划（制定博客目录）

> **用途**：调整章节边界、顺序、篇幅预算时执行。
> **频率**：低。首次已产出 [LEARNING_ROADMAP.md](../LEARNING_ROADMAP.md)。
> **注意**：本阶段**只做规划，不生成正文**。规划必须经本人确认后才进入写作。

---

## 提示词正文（复制以下内容给 Agent）

```text
你是一名 Android 技术作者兼教材结构设计者。

请基于以下已有文档与真实源码，修订 docs/android-blog/LEARNING_ROADMAP.md
中的章节规划。不要撰写任何章节正文。

项目根目录：D:/Code/Android
必读输入：
  docs/android-blog/PROJECT_MAP.md
  docs/android-blog/SOURCE_INDEX.md
  以及规划中涉及的源码文件（必须实际打开，不得只靠文件名判断）

═══════════════════════════════════════════
一、读者与定位
═══════════════════════════════════════════

读者：具备基本 Java 语法（类、接口、继承、集合、异常）的 Android 初学者。
技术路线：Java + XML View + Android SDK / AndroidX。
目标：通过真实项目源码理解 Android 概念、API 用法与程序运行过程。
风格：严谨、清晰、重证据、重实践。不写成纯理论教材，也不写成操作步骤合集。

═══════════════════════════════════════════
二、规划要求
═══════════════════════════════════════════

1. 按知识依赖排序，不按模块或文件名排序。
   注意：本项目三个 Java 模块是平级并存的，章节必须能够横跨模块取材。
2. 每章聚焦一个明确主题，并回答一个真实存在的问题。
3. 不得为凑章节数而重复同一知识点。
4. 不得把项目中未实现的功能写成已有功能；缺素材的主题标为"扩展知识"。
5. 只有在前后关联明确时才合并章节；只有内容复杂且具备独立学习价值时才拆分。
6. **各章的篇幅预期必须由"素材密度"反推，而不是统一硬套一个字数。**
   请对每章评估素材密度（高 / 中 / 低），并据此给出合理的字数区间。
   如果某章素材只够 4000 字，就如实标出，并给出合并或补充实验的建议 ——
   **不要为了凑字数而重复概念**。
7. 篇幅口径统一为「正文可见字符（排除代码块、行内代码、Markdown 标记、空白）」，
   目标区间 6000～7000，详见 docs/android-blog/README.md。

═══════════════════════════════════════════
三、每章必须给出的规划信息
═══════════════════════════════════════════

- 章节编号与标题
- 学习目标
- 要解决的核心问题（一句话，最好取自代码中真实存在的困惑）
- 前置知识（章节号）
- 对应的真实源码文件与代码位置
- 计划解释的核心 API
- 计划展示的运行流程
- 适合安排的实验或练习（要写清预期现象与验证方式）
- 与前后章节的关系
- 素材密度评估（高 / 中 / 低）+ 理由
- 预计篇幅及内部篇幅分配

═══════════════════════════════════════════
四、输出
═══════════════════════════════════════════

1. 更新 LEARNING_ROADMAP.md：
   - 章节总表（编号 / 标题 / 核心问题 / 前置 / 素材密度 / 字数预算）
   - 章节依赖关系 Mermaid 图
   - 每章的详细规划卡片
   - 章节 ↔ 源码映射速查表
   - 待补充知识点清单（必须与 SOURCE_INDEX.md 第七节一致）
   - 写作优先级建议（说明为什么这样排序，而不是简单从第 1 章开始）
2. 在对话中回复：本次做了哪些调整、为什么调整、
   哪些章节你认为素材不足需要我决策。

═══════════════════════════════════════════
五、本项目已确认的硬约束（不要违背）
═══════════════════════════════════════════

- :app 模块是 Compose + Kotlin，不属于博客范围
- 项目**只覆写了 onCreate**，没有任何其他生命周期方法，
  也没有 onSaveInstanceState —— "生命周期"章节必须靠实验任务补足，
  不能假装项目里有现成代码
- 项目**没有** Fragment / Navigation / RecyclerView / ViewModel /
  网络请求 / 本地存储 / 权限申请 / 自定义 View / 动画
- 有些 Activity 未在 Manifest 注册或已被注释，实验中需先取消注释

请先给出规划供我检查，不要立即生成章节正文。
```

## 使用说明

- 拿到规划后，**重点审三件事**：
  1. 章节顺序是否符合你的实际学习顺序（而不是理论最优顺序）；
  2. 每章的"核心问题"是否真的是你想问的；
  3. 素材密度判断是否诚实（有没有章节被硬撑到 7000 字）。
- 规划确认后，把它固化下来。**后续每次写单章都引用它，不要临时改结构** ——
  结构一动，已写的章节交叉引用就全断了。
